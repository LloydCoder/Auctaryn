Why we built this

A reported incident, and a real engineering problem.

On February 23, 2026, Summer Yue publicly reported that OpenClaw began deleting email after a large-inbox workflow and context compaction. TechCrunch reported the account but noted it could not independently verify the event. That incident highlights a gap between sandboxing an execution environment and checking the context used to make decisions. Auctaryn explores defense-in-depth controls, while acknowledging that submitted-context checks are heuristic and do not prove what an external agent actually consumed.

ThreatFade — the foundation
An optional advisory integration intended to consume network threat signals. Live upstream authentication, telemetry quality, false-positive rates and production availability require separate verification.
FusionOps — the threat hub
FusionOps is a separate service in the wider ecosystem. Auctaryn's repository and CI do not establish that a live FusionOps integration is configured or available.
Auctaryn — agent containment
Built to evaluate supported agent actions and integrate with OpenShell. CI covers repository behavior; live Platform/runtime acceptance and independent assessment remain pending. OWASP ASI01–ASI10 are mapped with varying implementation depth.
How we work

Test-driven. Honestly scoped.

Tests before code
Every module is built red-green-refactor. Tests are written first, watched to fail, then implemented against.
Honest status, always
We document what's MVP-depth vs. production-hardened. No category is claimed "covered" without working code behind it.
Fail-safe by default
When advisory analysis is unavailable, the local decision must remain authoritative: an upstream failure cannot grant approval. Runtime readiness and integration availability are reported separately.
Open-core, always
The repository declares Apache-2.0 licensing. Production use still requires live Platform/OpenShell acceptance, durable state and independent security review.
